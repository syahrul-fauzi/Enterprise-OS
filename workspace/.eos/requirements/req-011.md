# REQ-011: Visible Proof Panel untuk Requirements Page

## Status
🔥 ACTIVE — In Implementation (Front B)

## Requirement
**Tampilkan traceability dan proof status sebuah requirement secara end-to-end** sehingga manusia dapat melihat apakah requirement tersebut benar-benar terbukti — tanpa membaca source code atau membuka file .eos secara manual.

## Latar Belakang
REQ-010 membuktikan bahwa EOS mampu mengawal pekerjaan (vertical execution pipeline terbukti). Tapi EOS pipeline masih seperti mesin kotak hitam: manusia bisa melihat feature ada dan bekerja, tapi tidak bisa melihat BUKTI mengapa EOS mengatakan requirement tersebut proven.

REQ-011 harus membuktikan bahwa EOS dapat menjadi mesin yang membuat hubungan Requirement → Evidence dapat DILIHAT dan DIPAHAMI manusia. Ini langkah dari:
- "EOS capable mengawal pekerjaan" (REQ-010)
- Menjadi: "EOS mampu menjelaskan mengapa pekerjaan dianggap benar" (REQ-011)

## Enam Pertanyaan yang Harus Bisa Dijawab
Seseorang membuka satu requirement di UI, dan tanpa buka file lain bisa menjawab:
1. ✅ Apa yang diminta? (requirement description + acceptance criteria)
2. ✅ Di mana requirement tersebut ditrace? (RTM reference, requirementId trace)
3. ✅ Implementasinya apa? (file apa yang berubah, berapa baris, change type)
4. ✅ Evidence-nya apa? (evidence files, verification artifacts, architecture compliance)
5. ✅ Verdict-nya apa? (PASS/FAIL, confidence, decision fingerprint)
6. ✅ Apakah requirement tersebut benar-benar proven? (semua acceptance criteria met, all traces resolved)

## Acceptance Criteria
1. ✅ Satu halaman requirement dapat menunjukkan proof panel untuk requirement spesifik (via ?proof=req-XXX)
2. ✅ Proof panel menjawab ke-6 pertanyaan di atas tanpa perlu buka .eos manual
3. ✅ Navigasi antar requirement proof tersedia (selector untuk semua requirement verified)
4. ✅ Fallback ke static data jika runtime API belum terkonfigurasi (progressive enhancement)
5. ✅ Jika API /proof & /verification tersedia, gunakan runtime data; jika tidak, tampilkan data dari .eos evidence yang ada
6. ✅ Tidak ada refactor REQ-010, tidak ada abstraction baru, tidak ada dashboard besar
